ORBIT per-CGRA 2x2 predictor study — 2026-10-04

Decision: retain the existing candidate; no new deployment package or promotion.
Six matched-seed configurations did not establish a stable grouped-development
improvement. Network widths remain 64/32. The evidence points first to scarce
independent program groups and incomplete input information; it does not identify
softplus or the 80-update training budget as the dominant cause. A separate
ORBIT integration audit also found inconsistent downstream graph features for
matching source kernels; model loading success alone does not validate deployment.

Model audit
  Train/validation/test zero-residual fractions: 28.86%/26.28%/35.20%; mean
  prediction bias on those rows: +0.287/+0.412/+0.203 II. Ensemble clamp-at-20:
  0.54%/0%/2.63%. Per-member fractions are recorded separately.
  In development, 85 complete DFGs are misranked. All have lower-bound ties,
  but so do all 220 complete DFGs, so this co-occurrence is not explanatory.
  Only three errors select a true residual <=1; none has any saturated ensemble
  or member prediction. This audit includes training resubstitution, not OOF.

  At actual float32 precision, development has 19 exact compact61 collision
  buckets with different II, spanning 11 identities. Full148 separates 15
  buckets; four remain identical. There are 45 close-feature pairs at the
  predeclared standardized RMS <=0.05 threshold. Full-feature train statistics
  contain 36 constant/near-constant columns and three |correlation|>0.999 pairs.
  Compact out-of-training-range rows: validation 10/312, test 11/304.
  Graph summaries discard full adjacency; compact61 also drops opcode counts,
  attribute maxima and shape one-hot (rows, columns and capacity remain).
  These collisions demonstrate information loss, not that a larger network
  would fix it. No explicit operation latency appears in original inputs or
  canonical ORBIT tasks. No invented FU latency features were added; opcode
  counts are the verified available operation-mix features.

  Effective loss mass is 50% random, 50% program, uniform over groups within
  each stratum and successful rows within a group. Normalization is originally
  unweighted over successful training rows (1,256/1,469 rows are random, about
  85.5%, despite their 50% loss mass). The old report's wording that all
  groups are equal with random groups halved was inaccurate; future trainer
  text is corrected, while the protected original report remains unchanged.

Controlled experiments
  Six configurations x four seeds (17,41,113,239) x four partitions =96 fits.
  Partitions: original train/validation plus three outer grouped development
  folds; each outer fit selects checkpoints using an inner group holdout.
  Outer labels do not choose its checkpoint. Original loss/optimizer and
  widths 64/32 are retained: AdamW lr=.002, wd=.0001; SmoothL1 +.1 pairwise
  hinge +.3 set-top1. No grid search and no mapper-success head.
  Selection priority: equal-stratum source-group validation regret, then hit,
  then MAE, earliest epoch on ties. reference80 uses exactly 80 updates.
  weighted400 changes normalization to loss-consistent weights. direct400 uses
  positive softplus II capped at20 for training, without the lower-bound floor;
  inference applies max(lower_bound,min(20,prediction)). opcode400 restores
  11 opcode counts (72 inputs). The sixth combines opcode and weighted norm.
  No measured latency features were available. All nonreference fits allow
  at most 400 updates and select their own inner-validation checkpoint.

Practical conclusion and next data
  Improvements delivered are auditable evaluation, bounded grouped experiments,
  fresh native test outcomes and a corrected opt-in 2x2 cost-catalog domain
  check. No stable weight improvement was established. Longer fitting and
  direct II output alone are not supported as fixes. Richer operation features
  remove many collisions, but their aggregate gain does not survive every fold.

  First align ORBIT integrated graph extraction with the native/pre-mapper
  feature contract and repeat same-input parity. Continue data collection, but
  prioritize independent program source groups and
  ORBIT-sized loop/task bodies over more random graphs or more variants of the
  same benchmark. The large flattened MachSuite DFGs expose severe native-search
  coverage limits; first make real task extraction/lowering reproducible, then
  add attention/reduction/convolution, blocked GEMM/GEMV, real tiling/unrolling
  and fusion/fission lineages, at documented budgets. Keep final benchmark
  families evaluation-only. Do not loosen exclusions to make the dataset larger.
  Variants help measure transform sensitivity but do not enlarge independent N.

  ML improves pooled II error and low-budget shortlist quality over analytical
  on the original mostly-random test. It does not uniformly beat fixed4x4 or
  analytical at every budget, and program-only evidence is too small and censored
  to justify a whole-program speedup, calibrated uncertainty or safe pruning.
